IB Diagnostics
On-demand only — nothing here runs in cron unless you explicitly enable scheduling.

Local Fabric Scan (container, direct IB)

Runs ibnetdiscover / iblinkinfo / sminfo / ibqueryerrors directly from this container (it has direct UMAD access on the IB-connected node). No switch SSH and no ibdiagnet bundle needed — lightweight, and it surfaces real per-port error counters (LinkDowned / SymbolErrors / PortXmitDiscards) that the UFM REST API does not expose.

Fabric Diagnostic (ibdiagnet)

ibdiagnet is fabric-wide from a single vantage point — it runs on one IB-connected node and scans the entire subnet from there (you do not run it per switch). It parses the output into a compact report and discards the 2-3 GB of raw files (retention keeps the latest archive for download): routing, PHY, rail validation, per-lane PM, cable info, SM/PM state.
Note: the target must have the ibdiagnet binary + IB access. MLNX-OS switches are CLI-only and cannot run it — pick the UFM appliance (set UFM_SSH_HOST), or just use the Local Fabric Scan above (runs in this container, already covers the whole fabric, no setup).
Set up UFM SSH (run ibdiagnet on the UFM appliance)
Installs the collector SSH key on the UFM host (password used once) and verifies ibdiagnet runs in the container. Then the UFM appliance appears as a target above.
